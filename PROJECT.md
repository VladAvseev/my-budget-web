ТЕХНИЧЕСКОЕ ЗАДАНИЕ: UI КОМПОНЕНТЫ И ФУНКЦИОНАЛ 0. СТРУКТУРА ПРИЛОЖЕНИЯ

Приложение имеет единый Layout для авторизованных пользователей, который включает:

    Sidebar (Боковая панель)

    Content Area (Область контента)

Страницы Авторизация и Регистрация отображаются без Layout, на всю страницу.

5.0. Общие элементы для разделов Расходы, Отложено, Доходы

Примечание: данный раздел не применяется к Ежедневным расходам.
Панель управления списком операций

Располагается над списком операций внутри вкладок «Расходы», «Отложено», «Доходы».

    Контент:

        PrimaryButton «Добавить».

            Функционал: Открывает Modal "Добавить операцию".

        Toggle «Группировать по категориям».

            Функционал:

                В состоянии off: операции отображаются плоским списком.

                В состоянии on: операции группируются по категориям в компоненты Accordion.

                Операции без категории объединяются в группу «Без категории».

                Состояние переключателя сохраняется независимо для каждой вкладки.

Принцип группировки

    Группировка включена (Toggle в состоянии on):

        Операции группируются по полю category.

        Каждая группа отображается в компоненте Accordion.

        В props.header компонента Accordion передаётся контент, содержащий:

            Название категории (или «Без категории»).

            Сумму всех операций в данной группе.

        Операции без категории (category: null) попадают в группу «Без категории».

        Внутри Accordion (в props.children) передаётся OperationsList с элементами OperationsListItem (без изменений в их структуре).

        Группы сортируются по алфавиту (по названию категории), группа «Без категории» отображается последней.

    Группировка выключена (Toggle в состоянии off):

        Операции отображаются плоским списком без группировки.

Accordion в режиме группировки

    Функционал:

        При клике на Header группа сворачивается/разворачивается.

        Состояние сворачивания/разворачивания каждой группы сохраняется независимо в рамках сессии.

5.1. Ежедневные расходы (DailyExpenses)

Особенность: Ежедневные расходы не поддерживают категории и группировку по категориям. Операции всегда отображаются плоским списком. Вкладка «Ежедневные расходы» отображается только если hasDailyExpenses = true.

    Контент:

        Панель управления:

            PrimaryButton «Добавить».

                Блокировка: Кнопка переходит в состояние disabled, когда количество добавленных операций равно количеству дней в отчётном периоде (от Начало отчётного периода до Конец отчётного периода).

        OperationsList: Список операций (всегда плоский список без группировки).

            Принцип FILO (First In, Last Out):

                Добавление: Каждая новая операция автоматически получает следующую доступную дату в хронологическом порядке. Первая добавленная операция привязывается к дате Начало отчётного периода, вторая — к следующему дню, и так далее.

                Удаление: При удалении операции ее дата становится вакантной. Новая операция займет эту дату, следуя тому же принципу последовательного заполнения (заполняется ближайшая доступная дата от начала периода).

                Редактирование: При редактировании операции изменяются только сумма и описание. Дата операции не редактируется.

        OperationsListItem:

            Состав:

                Сумма операции.

                Сумма опережения/отставания от ежедневного бюджета.

                Иконка, отображающая опережение/отставание от ежедневного бюджета.

                Дата операции (автоматически назначенная, нередактируемая).

                Описание.

                IconButton "Редактировать".

                IconButton "Удалить".

            Функционал:

                Клик на IconButton "Редактировать" открывает Modal "Редактировать операцию".

                Клик на IconButton "Удалить" открывает ConfirmActionModal удаления операции.

    Modal "Добавить операцию" (Ежедневные расходы):

        Заголовок: «Добавить операцию (Ежедневные расходы)».

        Контент:

            TextInput «Сумма» (обязательное, тип: число).

            TextInput «Описание» (необязательное).

            ErrorBanner (например, «Ошибка при добавлении операции»).

        Footer: SecondaryButton "Отмена", PrimaryButton "Сохранить".

            Состояние: Кнопка «Сохранить» в состоянии disabled, пока поле «Сумма» не заполнено.

    Modal "Редактировать операцию" (Ежедневные расходы):

        Заголовок: «Редактировать операцию (Ежедневные расходы)».

        Контент:

            TextInput «Сумма» (заполнено текущим значением).

            TextInput «Описание» (заполнено текущим значением).

            ErrorBanner (например, «Ошибка при сохранении»).

        Footer: SecondaryButton "Отмена", PrimaryButton "Сохранить".

        Примечание: Поле даты отсутствует, так как дата операции не подлежит ручному редактированию.

    ConfirmActionModal "Удалить операцию" (Ежедневные расходы):

        Заголовок: «Удаление операции».

        Контент: «Вы действительно хотите удалить операцию?».

        Footer: SecondaryButton "Отмена", DangerButton "Удалить".

        Функционал: При подтверждении операция удаляется, ее дата освобождается. Кнопка «Добавить» становится активной, если ранее была заблокирована.

БАЗА ДАННЫХ POSTGRESQL

1. Таблицы
   1.1. Таблица users
   Поле Тип Ограничения Описание
   id SERIAL PRIMARY KEY Уникальный идентификатор
   login VARCHAR(50) UNIQUE, NOT NULL Логин пользователя
   password_hash VARCHAR(255) NOT NULL Хеш пароля
   initial_balance DECIMAL(15, 2) NOT NULL DEFAULT 0 Начальный баланс
   created_at TIMESTAMP NOT NULL DEFAULT NOW() Дата создания
   updated_at TIMESTAMP NOT NULL DEFAULT NOW() Дата обновления

Вычисляемое поле (не хранится в БД, рассчитывается на уровне приложения):

    Баланс = initial_balance + сумма всех операций типа income − сумма всех операций типов expense и deferred по всем отчётам пользователя.

1.2. Таблица categories
Поле Тип Ограничения Описание
id SERIAL PRIMARY KEY Уникальный идентификатор
user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE Владелец категории
name VARCHAR(100) NOT NULL Название категории
created_at TIMESTAMP NOT NULL DEFAULT NOW() Дата создания
updated_at TIMESTAMP NOT NULL DEFAULT NOW() Дата обновления

    Уникальность: UNIQUE(user_id, name) — у одного пользователя не может быть двух категорий с одинаковым названием.

1.3. Таблица reports
Поле Тип Ограничения Описание
id SERIAL PRIMARY KEY Уникальный идентификатор
user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE Владелец отчёта
name VARCHAR(200) NOT NULL DEFAULT 'Новый отчёт' Название отчёта
daily_budget DECIMAL(15, 2) NOT NULL DEFAULT 0 Ежедневный бюджет
period_start DATE NOT NULL Начало отчётного периода
period_end DATE NOT NULL Конец отчётного периода
has_daily_expenses BOOLEAN NOT NULL DEFAULT TRUE Включены ли ежедневные расходы
created_at TIMESTAMP NOT NULL DEFAULT NOW() Дата создания
updated_at TIMESTAMP NOT NULL DEFAULT NOW() Дата обновления

    Проверка: CHECK(period_end >= period_start) — дата конца периода не может быть раньше даты начала.

    Примечание к has_daily_expenses:

        По умолчанию TRUE — ежедневные расходы включены для всех новых отчётов.

        При переключении на FALSE все операции типа daily_expense для данного отчёта удаляются.

1.4. Таблица operations
Поле Тип Ограничения Описание
id SERIAL PRIMARY KEY Уникальный идентификатор
report_id INTEGER NOT NULL REFERENCES reports(id) ON DELETE CASCADE Отчёт, к которому относится операция
category_id INTEGER REFERENCES categories(id) ON DELETE SET NULL Категория операции (опционально, только для expense, deferred, income)
type VARCHAR(50) NOT NULL Тип операции
amount DECIMAL(15, 2) NOT NULL Сумма операции
description TEXT Описание операции
operation_date DATE NOT NULL Дата операции
sort_order INTEGER NOT NULL DEFAULT 0 Порядок сортировки (для FILO в ежедневных расходах)
created_at TIMESTAMP NOT NULL DEFAULT NOW() Дата создания
updated_at TIMESTAMP NOT NULL DEFAULT NOW() Дата обновления

Пояснения к полям:

    category_id: Применимо только для типов expense, deferred, income. Для daily_expense значение всегда NULL. При удалении категории (ON DELETE SET NULL) операции не удаляются, а теряют привязку к категории.

    operation_date: Для операций типа daily_expense дата назначается автоматически по принципу FILO. Для остальных типов выбирается пользователем или устанавливается текущая дата.

    sort_order: Для операций типа daily_expense используется для реализации принципа FILO. При добавлении новой ежедневной операции sort_order получает следующее доступное значение. При удалении операции её sort_order освобождается и может быть переиспользован.
